# 示例：一篇可维护的 Markdown 技术文章

这是一篇用于展示本站写作格式的示例，不是正式研究报告。它演示如何用 Markdown 组织摘要、核心结论、正文、代码和参考资料，以及如何说明 AI 参与和核查状态。文章源文件保存在 GitHub 中，发布和修订都有版本记录。未来写作时可以复制仓库中的模板，替换标题、日期、分类与正文，再通过本地预览检查结构和链接。这里的内容只服务于维护流程说明，不包含未经验证的行业结论。

## 核心结论

- 一篇文章对应一个 Markdown 文件，分类、标签和日期写在文件顶部。
- `slug` 决定文章地址，发布后保持稳定，方便长期引用。
- 修改结论时同步更新日期，并在文末留下原因。

## 正文分析

### 让结构服务于阅读

标题描述问题，摘要交代范围，核心结论帮助读者判断是否继续阅读。正文使用二、三级标题展开，右侧目录与标题锚点方便返回重点段落。

### 让步骤可以复现

代码块注明语言，便于语法高亮和一键复制：

```bash
python -m mkdocs build --strict
```

该命令将文档构建为静态网页，并将构建警告视为错误。它能检查构建问题，但不能证明文章中的事实准确，也不能替代实际页面检查。

### 区分证据与判断

| 内容类型 | 建议写法 |
| --- | --- |
| 可验证事实 | 给出来源和适用版本 |
| 根据事实的推断 | 交代假设和推理过程 |
| 个人观点 | 标明立场，避免写成普遍规律 |

引用应链接原始材料；需要补充背景时，可以使用脚注。[^source]

## 实践建议

发布前检查：标题是否清晰、摘要是否完整、引用是否支持结论、代码是否测试、AI 参与情况是否准确。具体操作见[写作指南](../../../guides/writing.md)。
